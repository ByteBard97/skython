# CommonLibSSE-NG API verification (2026-09-30)

Checked by reading the headers of a fresh `git clone --depth 1 -b ng https://github.com/alandtse/CommonLibSSE-NG`. Nothing here was compiled by this part of the work; compile results from the Windows box are recorded separately by whoever ran Part 2. Header paths are relative to `include/`.

## Pin

- Commit `39f9d07a6ffabea8fb559eee87ab7d27cd463e8a`, 2026-09-30, `chore(release): 10.1.0 [skip ci]`. Project version 10.1.0 (`CMakeLists.txt`: `project(CommonLibSSE ... VERSION 10.1.0)`).
- CHANGELOG mentions AE 1.7.99 (`rel: support AE 1.7.99 address library format 5`, `re: model AE 1.7.99 layout changes`, `state: version AE>=1.7.99 frame fields`) and `flag for address library v5 compatibility`. It does **not** contain the string `1.7.104` (grep returned nothing). Task 0 Step 3's grep `1\.7\.99|1\.7\.104` still matches (on 1.7.99); the "if it does not" fallback is not triggered.
- CMake options (all in the root `CMakeLists.txt`): `REX_OPTION_INI`, `REX_OPTION_JSON`, `REX_OPTION_TOML` (OFF), `SKSE_SUPPORT_XBYAK` (OFF), `SKSE_SUPPORT_PATCH_SAFETY` (ON), `ENABLE_SKYRIM_SE` (ON), `ENABLE_SKYRIM_AE` (ON), `ENABLE_SKYRIM_VR` (ON), `BUILD_TESTS` (ON), `COMMONLIB_ENABLE_IPO` (ON). The plan's names (`BUILD_TESTS`, `ENABLE_SKYRIM_VR`) exist. The grep in Task 0 Step 3 (`option\(ENABLE_SKYRIM_(SE|AE|VR)|option\(BUILD_TESTS`) matches.
- CMake target: `CommonLibSSE`, alias `CommonLibSSE::CommonLibSSE` (matches the plan's `target_link_libraries`). It links `spdlog::spdlog`, `Microsoft::DirectXTK` and system libs publicly. Its CMake needs `find_package(spdlog)`, `find_path(rapidcsv.h)`, `find_package(directxtk)`.
- With `SKSE_SUPPORT_PATCH_SAFETY=ON` (default) the configure step runs `FetchContent` for `https://github.com/TsudaKageyu/minhook.git` (tag v1.3.4): the box needs git and network access during configure. Set `-DSKSE_SUPPORT_PATCH_SAFETY=OFF` to avoid it.
- `vcpkg.json` (root): `builtin-baseline ee12231b20c95013c6638d845d04c91559a1d1ff`; dependencies `vcpkg-cmake-config` (host), `directxmath`>=2025-04-03, `directxtk`>=2025-10-27, `fmt`>=12.1.0, `nlohmann-json`>=3.12.0, `rapidcsv`>=8.90, `simpleini`>=4.25, `spdlog`>=1.16.0, `toml11`>=4.4.0, `xbyak`>=7.28; feature `tests` (catch2) is a **default feature**. The actual add_subdirectory build only calls `find_package` for **spdlog, directxtk, rapidcsv** (plus the headers of directxmath, which directxtk pulls in). The precedent manifest (rapidcsv + spdlog only, for v3.7.0) is therefore **too small** for 10.1.0: it additionally needs `directxtk`. Copying the whole list verbatim, as Task 1 says, has two traps: the `version>=` constraints require a `builtin-baseline` in the consuming manifest (vcpkg errors without one), and `catch2` is not wanted.
- `std::format`: the library builds as C++23 (`cxx_std_23` PUBLIC); MSVC 17.14 provides `<format>`. CommonLib itself uses `fmt` via spdlog. Task 1's `#include <format>` is fine.
